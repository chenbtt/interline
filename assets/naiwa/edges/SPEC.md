# 奶蛙贴边素材规格 v4

吸附到屏幕边缘时用的精灵图：**八向 × 三相位，共 24 张**。会眨眼，鼠标压上来会抬爪；朗读时嘴会跟着开合。身体始终不动，只换表情和手，口型是运行时画上去的一小块，不占素材。只含美术，不含吸附逻辑。

## 一句话规则

**画布贴着屏幕的那条边，就是切口所在的那条边。**

接入时不需要记任何裁剪偏移量：把图按画布原点贴上去，抬到屏幕边缘即可。切口之外的像素全是透明，不会盖住底下的窗口内容。

## 文件清单

```
edge-{dir}-{phase}.png        # 8 × 3 = 24 个，同一个目录
```

`dir` 是被遮挡的那一侧，`phase` 是 `base`（常态）/ `blink`（眨眼）/ `hi`（抬爪）。同方向的三张共用一张画布、一条切口，也共用同一个身体位置，换帧时不会横跳。

| 方向 | 被遮挡的一侧 | 画面上能看到的 | 对齐的屏幕边 | base 帧可见包围盒 | `hi` 帧包围盒 |
| --- | --- | --- | --- | --- | --- |
| `n` | 上（整条背出画） | 头朝下 + 两只前爪扒住边缘，看得见的是**背**，没有肚皮 | 上边 | (34, 0, 221, 150) | (34, 0, 242, 150) |
| `s` | 下（切 50%） | 头 + 举起的右手，身子在边缘之下 | 下边 | (58, 144, 193, 256) | (23, 143, 193, 256) |
| `w` | 左（切 50%） | 右半身，脸朝右（朝屏幕内侧） | 左边 | (0, 26, 70, 240) | (0, 25, 105, 240) |
| `e` | 右（切 50%） | 左半身，脸朝左（朝屏幕内侧） | 右边 | (186, 26, 256, 240) | (151, 25, 256, 240) |
| `nw` | 左（切 45%） | 头 + 右半身，斜着从角上探出来 | 左边 + 上边 | (0, 0, 77, 214) | (0, 0, 112, 214) |
| `ne` | 右（切 45%） | 头 + 左半身，斜着从角上探出来 | 右边 + 上边 | (179, 0, 256, 214) | (144, 0, 256, 214) |
| `sw` | 左（切 45%） | 头 + 右半身，从下往上斜探 | 左边 + 下边 | (0, 42, 77, 256) | (0, 41, 112, 256) |
| `se` | 右（切 45%） | 头 + 左半身，从下往上斜探 | 右边 + 下边 | (179, 42, 256, 256) | (144, 41, 256, 256) |

包围盒是「可见像素」的 `(x0, y0, x1, y1)`，不是不透明矩形的边界——顶到 0 或 256 的那一侧，说明像素确实压到了画布边，没有留缝。同一方向的三张里这一侧**始终**是 0 或 256。

`hi` 帧比 `base` 宽一截（顶边 +21 px、侧姿态 +35 px），宽出来的全是那条举起来的手臂。**手臂只往屏幕内侧长，绝不越过切口那一侧**——切口是屏幕边缘，手不可能伸到屏幕外面去。

## 相位与播放

| 相位 | 内容 |
| --- | --- |
| `base` | 常态，睁眼，手垂着 |
| `blink` | 眨眼，只换眼睛，姿态与 `base` 逐像素对齐 |
| `hi` | 抬爪，把垂着的那只手抬到脸侧；眼睛是睁着的 |

吸附态的**身体是静止**的，会动的只有两处：眨眼 / 抬爪（换素材图），以及朗读时的口型（不换图）。三套各自独立，可以叠加——张嘴的时候照样眨眼、抬爪，互不打断。

```
base ──（停 2~4 秒，随机）──> blink ──（160 ms）──> base      # 眨眼
base ──（鼠标进入）──────> hi ────（鼠标离开）───> base      # 抬爪
嘴线 ──（朗读中，10fps）──> 开合 ──（停下）────────> 闭嘴      # 口型
```

### 朗读口型（v57）

不新增 PNG。每个方向在 `meta.json` 里多一个 `mouth: [cx, cy, angle]`，是 256 画布坐标下嘴线的中心与主轴倾角，由 `make_pet_edges.py --mouth` 逐向量出来：暖棕色细长连通域（`10≤w≤26`、`2≤h≤10`、`w/h≥1.5`）取面积最大者，再用 PCA 求主轴角，归一到 `[-90, 90)`。八个方向里七个是斜侧脸，嘴线 ±28.4°；顶边 `n` 是倒着的头，接近水平（7.2°），位置也跟其余七向不成规律，必须单独量。

三个相位之间量到的嘴位差 ≤1.4px、倾角差 ≤0.6°，所以共用同一组坐标，不用按相位分别存。

时间轴独立于相位状态机：12 帧 @10fps（1.2 秒一轮，两次短开合 + 长停顿），比站立形态的 16fps 缓。贴边嘴只有 14px 宽又带倾角，照搬会显得碎。停下朗读立刻闭嘴，不循环。

绘制时沿嘴线法线偏 `h*0.45`，让原来那条嘴线正好落在口腔上缘，看着是「嘴张开了」而不是「嘴线变粗了」。注意两个坐标约定：

- `cx / cy / angle` 是**未缩放**的 256 画布坐标，画的时候要乘缩放系数，`origin` 与素材图同一个画布左上角。缩放不匹配（图乘 k、嘴不乘）时深色块会整体偏到脸外，窗口几何和「嘴部有像素变化」都测不出来——`--edgecheck` 现在直接比对闭口 / 张口两格的差异质心与预期嘴位。
- PIL 的 `rotate()` 逆时针为正，Qt 的 `QPainter.rotate()` 顺时针为正。图像坐标（y 向下）量出来的 `angle` 在 QPainter 里直接用，在 PIL 原型里要取反，否则口型和嘴线交叉成 X。

**抬爪是交互，不是循环。** 鼠标指针压在蛙身上才 `hi`，移开立刻回 `base`；不要做成「点一下抬一次」的定时动画，也不要让 `hi` 自己播完回去——鼠标还在上面时手放下来，等于没反应。

`blink` 和 `hi` 会撞车，按下面的优先级：

- 处于 `hi` 时不眨眼。抬手是个短促的动作，中途眼皮一合会显得抽搐。
- 鼠标进来的瞬间如果是 `blink`，等它闪完（160 ms）再切 `hi`，别硬切。
- 鼠标离开时回 `base`，不要回「离开时的相位」。

眨眼不进任何循环，隔几秒闪一次就够。连续眨会显得神经质，按固定 2 秒更假；建议 2–4 秒之间随机，连眨两次的概率留低一点（比如 8%）。

不做呼吸是刻意的：顶边那张的呼吸动的是头，稍微给多一点就像在引体向上；侧姿态那点躯干胀缩在 256 px 上几乎看不出来。收益不值得两倍素材和一套呼吸状态机。

## 尺寸与格式

| 项 | 值 |
| --- | --- |
| 画布 | 256 × 256，正方形（四角要留斜探的空间，非正方形会切掉手） |
| 格式 | PNG，RGBA 8 bit/通道（32 位），sRGB |
| 背景 | 全透明，无投影、无描边、无地面阴影 |
| 文件数 / 总体积 | 24 张 / 566 KB，平均 23 KB（另有 `meta.json`，8 个方向的可见包围盒 + 嘴位） |
| 可见内容 | 左右 70×214，下边 135×112，顶边 187×150，四角 77×214；覆盖率 14–34%（`hi` 帧多 8–16 个百分点） |
| 与站立帧的比例 | 站立帧 192×208。除顶边外可见高 214（大 2.9%）；顶边按头宽对齐，见下 |

比例是按游戏帧（`manifest.json` 的 `frame_w/frame_h`）校准的，不是按屏幕分辨率。所以接入时**不要**再按窗口尺寸二次拉伸，用 256 画布 1:1 或等比例缩放即可。

如果要跟随「设置 → 奶蛙大小」，把整张图按同一系数缩放，切口照样落在缩放后的窗口边上——这条规则对缩放不敏感。

## 命名规范

```
edge-{dir}-{phase}.png
```

- `dir` ∈ `n` `ne` `e` `se` `s` `sw` `w` `nw`，全小写，无下划线
- `phase` ∈ `base` `blink` `hi`
- **`dir` 指的是被遮挡的那一侧，不是露出来的那一侧**。吸附到屏幕左边 → 左边被切 → `w`
- 八向三相位齐全；`blink` / `hi` 缺文件就退回 `base`，不要留空窗

## 方向映射

| 吸附目标 | 文件前缀 | 窗口怎么摆 |
| --- | --- | --- |
| 屏幕上边 | `edge-n-*` | 窗口上边 = 屏幕上边，沿 X 轴跟随拖动 |
| 屏幕下边 | `edge-s-*` | 窗口下边 = 屏幕下边，沿 X 轴跟随拖动 |
| 屏幕左边 | `edge-w-*` | 窗口左边 = 屏幕左边，沿 Y 轴跟随拖动 |
| 屏幕右边 | `edge-e-*` | 窗口右边 = 屏幕右边，沿 Y 轴跟随拖动 |
| 四角 | `edge-{角}-*` | 两条边同时对齐，完全吸附不动 |

四角优先于四边：到竖边和横边的距离**都**小于阈值时按角落处理，否则取更近的那条边。**v59 起阈值是 10 px**（原先 64 px，画布 256 的 1/4）。64 px 的问题是拖窗口路过屏幕边缘就误吸——用户往往只是想把蛙从屏幕中间挪到偏一点的位置，松手却飞到边上去了。改成「几乎贴上才吸」之后，吸附变成明确意图而不是拖放的副产物。`--edgecheck` 里 11px 不吸 / 10px 吸 / 9px 吸，横竖两轴都各有一组用例。

距离按**蛙可见部分的边缘**到屏幕边算，不是按中心。按中心算的话，左右贴边要把蛙拖到过半出屏幕才吸得上——站立形态的蛙有 173 px 宽，中心进到阈值以内，意味着它已经有一多半在屏幕外了。四角同理，用边缘距离时「两条边都近」才真的是在角落里。蛙已经被拖出屏幕时距离按 0 算，松手直接吸回来。

## 落位与判定（`pet_edge.py`，已实现）

吸附逻辑在 `pet_edge.py` 里，只做三件事，不认识 QWidget：

| 函数 | 职责 |
| --- | --- |
| `pick_dir(frog, screen, snap, blocked)` | 松手时判定吸到哪条边；`blocked` 是多屏时相邻的那条边 |
| `snap_pos(d, base_box, canvas, scale, size, anchor, screen, off)` | 算出窗口该放哪；`size` 是整窗（含气泡），`off` 是画布在窗口里的偏移（只对自由轴有用） |
| `EdgeState` | `base` / `blink` / `hi` 三个相位的推进，外加一条独立的朗读口型时钟（10fps） |

`snap_pos` 的两轴规则不一样，这是整套素材的硬约束推出来的：

- **贴边那一轴由屏幕边直接算出**，不参与 clamp。窗口边缘离开屏幕边，切口就离了屏幕边；这一轴上画布永远顶着切口那一侧，所以窗口边就等于画布边，气泡的偏移不参与计算；
- **自由那一轴**按「可见部分的中心」对上拖放点，再夹进屏幕内（夹的是整窗，气泡也得留在屏幕里）。上下贴边时自由轴是 x，左右贴边时是 y，此轴要减掉画布在窗口内的偏移；
- 四角两条轴都贴，没有自由轴。

多屏时相邻的那条边不吸——外面还是桌面，吸过去等于卡在两块屏中间。判定要拿**整块屏**的几何去探，不能用 `availableGeometry`：任务栏那块属于同一块屏，用可用区探会把有任务栏的那条边误判成相邻屏。

## 接入要点

1. 吸附态窗口**不是** 256×256：里面除了这一帧，还带着当前这句的气泡。气泡摆在屏幕内侧、尾巴朝蛙，窗口因此比画布宽一截（左边贴边时窗口往右长）。所以断言「贴边」要判**画布**，不是窗口——`--edgecheck` 里就是这么写的。气泡接的是蛙**可见盒**（全相位并集 `box`）那条边，不是画布边：`w` 的可见部分只有 70px 宽，按画布边摆气泡会离蛙一大截；用并集盒则抬手帧那只手不会被气泡压住。尾巴的落点在可见盒从上往下 18% 处，那里是嘴。
2. 换帧**只换图，不动窗口位置**。切口是靠窗口贴边实现的，重算位置反而会把切口推离屏幕边。
3. 窗口位置由「对齐边」算出来，不需要读图里的像素：左/上贴边取 `0`，右/下贴边取 `屏幕宽 - 256`。
4. 拖离吸附位时切回站立姿态（`idle` 或 `running-*`），两者尺寸差 2.9%，肉眼看不出来，可以硬切。切的时候以**可见部分的中心**为锚，蛙才不会跳。
5. 多屏时以宠物当前所在的屏幕为准（`QScreen.availableGeometry()`，不是 `geometry()`——后者含任务栏区）。
6. **判定 hover 要按 alpha，不能按窗口矩形。** 窗口是 256×256，但可见像素只占 14–34%，左右贴边时半边都是空的。`enterEvent` 在整个矩形上都会触发，指针还离蛙十几像素它就开始挥手了。在 `mouseMoveEvent` 里采当前帧的 alpha，低于 24 才算没碰上。
7. 打包时按 `meta.json` 里列的方向与相位逐条收图，别手抄清单：漏一张只在打包版里表现为「图加载不出来」，源码跑一切正常。`Interline.spec` 现在用 glob 展开并断言数量。

## 吸附态窗口几何与悬停工具条（v59）

**窗口几何不随台词变。** 旧版气泡高度由当前这句的行数决定，`hgt = max(c, by + bh)`：3 行时窗口比画布高，切到 2 行时被夹回画布高度 `c`，气泡底下多出十几像素全透明区，透出桌面就是用户看到的「底部缝隙」。v59 把吸附态气泡的宽高固定成「`pet.bubble_w` × `BUBBLE_MAX_LINES` 行」，气泡槽位恒定，换句只换里面的字。实测顶部贴边 3 行 → 2 行：窗口 `360×268`、画布全局 `(525,0)`、蛙全局 `(556,0)`、五颗按钮坐标全部逐像素不变。

**工具带接在气泡背离蛙的那一侧**，从气泡边界直接开始、一直铺到窗口边，不留透明尾带：

| 切口 | 气泡位置 | 工具带位置 | 按钮对齐 |
| --- | --- | --- | --- |
| `top`（n / 顶部贴边） | 蛙下方 | 气泡下方，铺到窗口底 | 窗口左右沿 |
| `bottom`（s） | 蛙上方 | 气泡上方，贴窗口顶 | 窗口左右沿 |
| `left` / `right`（含四角） | 蛙旁边 | 气泡下沿，铺到窗口底 | 气泡左右沿（不压蛙身） |

五颗按钮仍是「左三 / 右二」，22px 见方。**工具带最窄 `TOOL_MIN_W = 142px`**：左三 78 + 右二 50 + 两端留白 8 + 组间距 6。v60 之前站立收起态直接拿蛙宽当工具带宽，奶蛙缩到 0.6 倍只有 115px，`next`(60–81) 与 `hide`(61–82) 重叠——后画的展开按钮盖住「下一句」（少一颗），命中按插入顺序却先撞 `next`（点展开变下一句，tooltip 也显示「下一句」）。现在站立态 `_metrics()` 把窗口加宽到至少 142、蛙居中（以窗口中心为锚，不跳），吸附态 `bw = max(bubble_w, 142)`。`--toolcheck` 逐向断言：按钮都在窗口内、任意两颗不重叠、点每颗都命中自己、工具带与气泡严丝合缝、工具带铺到窗口边、气泡中心在悬停带内；并覆盖 7 档缩放 × 气泡显隐、八向 × 收起/展开。

**悬停连续性靠三层**：① 工具带从气泡边界起，中间没有一格透明像素；② 悬停带是「气泡（含尾巴）∪ 工具带」再外扩 6px，`_hover_at` 里气泡、按钮、带上任意一点都算「还在」；③ 工具带铺一层 `alpha=1` 的底——Windows 分层窗口对 alpha=0 不做命中测试，不铺的话指针一进缝就掉到桌面、`leaveEvent` 立刻把按钮熄灭；`leaveEvent` 再给 180ms 宽限，指针回来就掐掉定时器。气泡收起时改由蛙身点亮工具条，那颗「收起」按钮变成向上折角，再点展开，不会把自己关进死角。

## 重新生成

```bash
python make_pet_edges.py --prep      # 从 sheet.png 切站立帧，出 1024 参考图（图生图用）
#   → 姿态图放 src/side/ 与 src/peek/，文件名带相位后缀
python make_pet_edges.py --build     # 抠图 → 相位对齐 → 摆位 → 八向三相位裁切
python make_pet_edges.py --sheet     # 八向 base 帧 3×3 预览
python make_pet_edges.py --context   # 模拟桌面贴边
python make_pet_edges.py --anim      # 胶片条 + GIF（验证眨眼与抬爪）
python make_pet_edges.py --mouth     # 只重量 8 向嘴位、写 meta.json，不动 24 张成品图
```

`--mouth` 是纯测量，不改一张 PNG；重跑前后 24 张图的 md5 汇总应当一致。换过素材或重跑 `--build` 之后记得再跑一次，嘴位是绑在具体像素上的。

源图命名：`pose_x.png` 是基准，`pose_x@blink.png` / `pose_x@hi.png` 是变体（`@in` / `@out` 是呼吸变体，现在不生成成品，但留着）。全部按 512 存，进仓库不进包——放 `build/` 里的话（那是 gitignore 的）重新克隆后会静默退化，而退化只有肉眼看得出来。

`--anim` 出两张：`screenshots/pet-edges-frames.png` 是 8 行 × 3 列的胶片条，看切口有没有逐帧漂移、身体有没有横跳；`screenshots/pet-edges-anim.gif` 是 w / s / n 三个方向「静一会儿眨眼、再抬爪」的循环。

`--build` 末尾会打一张包围盒表并统计不合格处，正常应该收在 `切口/侧边不合格 0 处`。它查两件事：切口那一侧必须顶到画布边；上下两条边的帧**不能**碰到画布左右边——那里是屏幕中间，被切了就是一条莫名其妙的直边。同时把各方向的可见包围盒写进 `meta.json`，运行时算吸附位置和命中区都靠它，所以这张表不用手抄进代码。

运行时自检：`python main.py --edgecheck` 跑 10px 阈值与方向判定的用例，再用**真窗口**贴八个方向抓图，断言画布与屏幕边齐平、切口那一条上有像素、气泡在屏幕内且不压住蛙、换相位窗口不动；口型部分验 8 向嘴位齐全、时钟能停在闭口、真窗口张嘴时嘴部像素确实变了、以及闭口 / 张口两格的差异质心落在预期嘴位上。最后拼出 `screenshots/pet-snap.png` 和 `screenshots/pet-edge-reading.png`（八向闭口 / 张口对照）。工具条、行数变化、悬停链、收起 / 主面板职责在 `python main.py --toolcheck` 里验，顺带出 `screenshots/pet-edge-tools.png`。

**自检配置隔离（v60）**：`--edgecheck` 用独立的 `%TEMP%/interline_check_edges/`，每次运行先清空，既不读用户配置也不读别的自检写下的残值。之前它和 `--toolcheck` 共用 `%TEMP%/interline_check/`，而 `--toolcheck` 会逐档改 `pet.scale`、经 `set_bubble_visible()` 把整份配置落盘，导致贴边画布从 230px / scale 0.90 漂到 154px / scale 0.60，`pet-snap.png`、`pet-edge-reading.png` 连配色一起变，md5 每次不同，回归图就没法用来判断改动有没有伤到绘制。隔离后五张回归图的 md5 与 v59 基线逐字节一致。

## 已知取舍

**只保留眨眼，不做呼吸。** 顶边那张的呼吸动的是头——挂着的东西一上一下，稍微给多一点就像在做引体向上；压到温和又基本看不出来。侧姿态动的是躯干胀缩，256 px 上一共 8 px，远看是噪声。权衡下来呼吸不值得两倍素材加一套状态机，只留眨眼。想恢复：把 `make_pet_edges.py` 里的 `BREATH` 改成 `True` 重跑 `--build`，源图（`src/*/@in.png`、`@out.png`）还在。

**朗读口型不违反上一条。** 动的是嘴，不是头或躯干，所以不会引体向上；而且它是运行时按 `meta.json` 画的胶囊，不新增素材、不换帧、不动窗口几何，成本跟做一套 8 向 × 12 帧的呼吸素材完全不是一个量级。

**抬手帧是重新生成的，必须做剪影对齐。** 图生图不会老老实实只改一只手：模型把整个蛙在画布里画偏了 35 px。按各自的包围盒摆位，鼠标一进来身体就横跳；顶边那张更糟，手直接顶出画布被切掉一截。所以 `_align()` 用「剪影重叠面积最大」求每帧的偏移——举起来的手伸在空白处，重叠为 0，挪到哪儿都不加分，最优解只由身体决定。**不要换成包围盒居中或重心对齐**，两者都会被那只手带偏（实测侧姿态 34 px、顶边 18 px）。

**所有相位共用一套摆位参数。** 切的是屏幕边缘，它不会因为蛙抬手而移动——所以裁切量按像素、按基准帧算，横向锚点也从基准帧取一次。按「当前帧宽度的 50%」去切，抬手帧宽 35 px，切口就漂 17 px。

**同一姿态的所有相位帧必须乘同一个缩放系数。** 这条是呼吸时代留下的，眨眼现在用不到，但改 `BREATH` 之后立刻会踩：吸气帧本来就比基准高 2%，逐帧各自缩到「固定高度」会把那一动抹平，播起来一动不动。`_scale()` 先用基准帧算 k，全体乘 k；另有一道预警，某帧高度偏离基准超过 15% 就报出来，那通常意味着源图分辨率不一致或者模型换了姿势。

**顶边要单独作画。** 蛙挂在屏幕上边之上，几何上可见的只能是身体下半截，头必然在屏幕外——四个角没这个问题，因为它们切的是竖边，头完整保留。所以顶边这张是另一次图生图：让模型画「趴在边缘上往下探，身体跑出画面上边被切平」，抠图后把可见像素顶到画布上边即可。

**提示词必须写清「看到的是背」。** 第一版只说了「往下探」，模型把头朝下之后顺手把奶白肚皮也画到了画面正中——从上后方看蛙，肚皮压在边缘上根本不该出现，这是视角前后矛盾。加上「必须看到背、纯黄、不许出现奶白肚皮」才干净。

**四角只切 45%，不是 50%。** 头在角色最上方，任何水平切口都会把头切掉，所以四角的遮挡全部交给竖边，垂直方向靠贴角（顶到画布边）来体现「在角落里」。代价是角的遮挡感比四边弱一档，45% 是「看得出被挡」和「保住脸」之间的平衡点。

**源图存 512 不存 1024。** 成品最大只有 224 px，512 大约是 2.3 倍采样，够用；1024 原图留在 `build/naiwa_edges/`（被 gitignore），要重出更精细的版本再从那儿取。24 张成品（566 KB）加 10 张源图（2.0 MB）共 2.5 MB 进仓库。
